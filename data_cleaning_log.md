# Data cleaning log

Every cleaning decision for the Baltimore 311 data (2023–2025), with the number of rows each one affected.

The table below is generated by [`sql/03_cleaning.sql`](sql/03_cleaning.sql). Each step writes its own row count into the `clean.cleaning_log` table in the same statement that makes the change, so these numbers are exactly what the script did. To see them yourself after running the pipeline:

```sql
SELECT * FROM clean.cleaning_log ORDER BY step;
```

## Before cleaning: a file-format fix

The city's CSV export leaves off the last two columns (`x`, `y`) on rows that have no map location: 295,297 rows in 2023, 319,383 in 2024 and 259,577 in 2025 (874,257 in total). PostgreSQL's loader rejects rows with too few fields, so [`scripts/fix_ragged_rows.py`](scripts/fix_ragged_rows.py) pads those rows with empty fields as the file streams into the database. No values are changed, and every file's row count after loading matches the city's published count exactly.

## Why these decisions

**Flag, don't delete.** Only 2 rows were removed (the test records). Everything else that would distort a measure is kept and flagged, so each analysis can decide what to include. For example, call-center questions count toward "how many people contacted 311", but not toward "how fast does the city fix things".

**Which rows are used for resolution times.** Each row is counted once, under the first reason that applies:

| Reason | Rows |
|---|---:|
| Call-center request | 1,026,178 |
| Proactive crew work | 445,345 |
| Duplicate | 68,719 |
| Transferred | 59,617 |
| Still open (New, Open, Pending or Hold) | 27,721 |
| Date problem | 3,453 |
| **Used for resolution times** | **1,407,186** |
| Total | 3,038,219 |

**Request types.** The city's type names start with a division code (`TRM-Pickup Pothole`). When work moves between divisions, the same issue appears under two codes, such as `TR-Street Cut Issues` and `TRM-Street Cut Issues`. The new `request_type` column drops the code, so the 326 published types become 308 issue names. The original name is kept in `sr_type`.

**Status.** The published status mixes two things: where the request stands (Open, Closed and so on) and why it was closed (Duplicate, Transferred), with inconsistent spelling. The cleaned data separates them into `status` plus two yes/no flags. Status is treated as the final word on whether a request is open, so a close date on an open request (step 19) is removed.

**Old neighborhood names (step 17).** In 2023 the city used a mix of older and current neighborhood names. Rather than guess, each old name was matched by taking the street addresses filed under it in 2023 and checking which neighborhood the same addresses were filed under in 2024–2025:

After all fixes, every neighborhood in the data is one of the 279 on the city's official list, so it joins cleanly to the 2020 population table.

**Missing neighborhoods are mostly expected.** 919,904 rows have no neighborhood. 874,257 of them have no address or map point at all, mostly people calling 311 with a question. Another 38,522 have a map point outside Baltimore City: the city's water utility also serves Baltimore County, so county water problems appear in city 311 data. The "outside" test uses the outermost latitude and longitude of every request that does have a city neighborhood (latitude 39.1992 to 39.3720, longitude -76.7113 to -76.5297). Only 7,125 rows (0.2%) are inside that box with no neighborhood.

**Closed before created (step 21).** Of these 31,400 rows, 26,847 were closed less than a minute before they were created. That looks like a logging-timing quirk, not a real time, and the top types are proactive crew work, which is logged after the job is done. The rows are kept for counts, but their resolution time is left blank.

**Missing agency (step 14).** `TRS-Parking Complaint` has an agency on every 2023 row, but the field came through blank on 21,496 of 37,501 rows in 2024 and 50,584 of 51,287 in 2025. Missing agencies are filled with the agency most often recorded for the same request type. The 320 left blank are types with no agency recorded anywhere (mostly `MOIT-` and `BPD-` types).

## Notes and limitations

- **Times are Baltimore local time** with no time zone attached (in 2025, requests peak at 1 PM and bottom out at 3 AM, which fits local time). Resolution times that span a daylight-saving change can be off by one hour.
- **"Still open" depends on when the city last updated each file.** The city last updated the 2023 file in January 2025, the 2024 file in December 2025, and the 2025 file on the day of download (2026-10-15). A 2023 request marked Open means open as of January 2025.
- **Resolution time** is close date minus created date, in hours and days. It is calculated by PostgreSQL as a generated column, so it always matches the dates.
